About FileGuard

Architectural philosophy, static heuristics design, and responsible cybersecurity disclosure.

Cloud Computing Architecture

Project Purpose & Cloud Role

FileGuard is a cloud-native cybersecurity file triage platform. In enterprise cloud architectures (such as ingest pipelines for AWS S3, Google Cloud Storage, or user-facing portals), executing untrusted files is hazardous.

FileGuard acts as the first-line static evaluation gatekeeper: it parses raw byte streams in memory, verifies file integrity through cryptographic hashes, evaluates byte distribution through Shannon entropy, and flags structural anomalies before files reach deeper systems.

Safety Guarantee & Realistic Limitations

  • Zero Execution Policy: Uploaded files are strictly treated as inert byte streams. They are never executed, interpreted, or loaded as active binaries.
  • Not a Complete Antivirus Replacement: FileGuard is an educational and static triage tool. It does NOT claim to detect 100% of malware, novel zero-days, or sophisticated runtime memory injections.
  • No Fake Engine Results: We do not fabricate vendor verdicts or simulate external proprietary scanning engines. All scores derive transparently from visible rules.

Core Heuristics Explained

1. Shannon Entropy Analysis

Measures byte-level randomness on a scale from 0.0 to 8.0. Normal text and structured code score between 3.5 and 5.5. Values exceeding 7.2 strongly indicate encryption (ransomware) or runtime binary packers (such as UPX).

2. Magic Byte Header Inspection

Attackers frequently rename malware.exe to invoice.pdf or photo.jpg. FileGuard reads the true initial bytes (magic numbers, e.g., MZ for PE executables) to catch disguised extensions.

3. Double Extension Camouflage

Exploits the Windows default configuration that hides known file extensions. Attackers name files payroll.docx.exe so victims only see payroll.docx.

4. Living-off-the-Land (LotL) Strings

Scans static binary strings for commands abusing native administrative binaries (e.g., powershell -enc, vssadmin delete shadows, certutil -urlcache, and bitsadmin).
